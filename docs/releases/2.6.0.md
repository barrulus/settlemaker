# 2.6.0 — measured village water and richer landscapes

Released 2026-09-11. Builds on 2.5.0's street-led city engine.
URL payload version remains 1; GeoJSON schema remains 4.

## Measured water

Villages of 1–1000 people accept `waterContext` v1. FMG supplies a complete
survey in burg-local metres, independent of population and harbour flags. A
shore 11 km away stays off the village tile; explicit empty surveys suppress
legacy bearings. Explicit polygons retain their physical position.

Water classification uses the filled union. Rendering, road verges, shoreline
walks and dock queries use exposed boundaries, preserving land islands while
removing polygon seams and survey crop edges. Planning queries are bounded by
the survey, and the final frame must retain a 1 km survey margin.

Successful library generation returns `waterContextResult`. Fatal errors throw
`WaterContextError` with the structured result. The accompanying web change
shows errors and warnings inside both previews and full pages without requiring
interaction. Unknown map units and unavailable local river widths are visible;
there is no automatic iframe resurvey protocol.

A burg strictly inside supplied water is an explicit location conflict, rather
than a village silently relocated onto land. Geometry/summary disagreements
retain the geometry and produce a warning. Ports without feasible nearby water
do not gain invented coastlines or docks.

The [full contract](../water-context-v1.md) specifies validation, precedence,
coverage, precision, polygon ownership, simple-coast eligibility and units.
City inputs with measured water remain unsupported; ordinary city inputs retain
2.5.0's glyphs, street-led layouts and capacity reporting.

## Other village changes since the production village engine

- FMG temple flags reserve an accessible henge clearing before fields and trees.
- Woodland fills unused field margins and surrounding ground according to biome.
- Optional river centreline surveys produce meanders; approaches curve while
  maintaining riverbank verges and short bridge crossings.
- Coastal roads check whole segments for water incursions; hamlet bays retain
  landscape-scale curvature.
- Tail trimming preserves occupied building clearance at shortened endpoints.

## Deployment and FMG activation

Deploy the library and settlemaker-web diagnostics together, with the web
submodule pinned to this release. Verify `/fmg` before enabling the sender.
Then FMG PR #81 can be merged and the fork rebuilt with:

```sh
VITE_SETTLEMAKER_WATER_CONTEXT_URL=https://settlemaker.com/fmg npm run build
```

The same setting works with `npm run dev` for local development. It is a
build-time setting; existing deployed FMG builds do not acquire it dynamically.
No FMG production setting is changed by this renderer release.

## Validation

See `output/water-context-review/` for local acceptance artifacts. Targeted tests
cover precedence, invalid inputs, body associations, distant/near shores,
islands, overlapping water, survey bounds, river widths and the city cutoff.
Browser checks exercise actual cross-origin previews with pointer events disabled.
The supplied Borteland map is loaded into the PR #81 exporter and its Tarrimas-Ha
payload rendered directly: no nearby sea, with a visible unavailable-local-river
warning from FMG's survey.

Validation record: the full thread-mode run exercised 1,389 tests; 1,386 passed
and three release-version expectations required updating from 2.5.0. After that
update, all 109 targeted release checks passed. Library, browser bundle and
review-script builds pass. The 60-case measured-water gallery has no generation
errors or unexpected water warnings; the web suite passes all 110 tests.

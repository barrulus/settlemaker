# settlemaker 2.5.0 — street-led cities and explicit capacity

Cities above population 1,000 now use the accepted refined village artwork.
Phase 1 city glyphs are retired from the default renderer. Ordinary homes use
consistent architectural families, one temple occupies a reserved site, and
parks have connected paths, central clearings and orderly planting.

Urban blocks are planned around street-facing rows, connected service alleys
and rear courtyard space. Corner ownership and joined neighbouring lots retain
dense street fronts. Glyphs fit their actual footprints and remain the same
physical size at every zoom. Difficult sites retain polygon fallback.

## Capacity and performance

Fixed seed 2, with the review fixture's three approach roads:

| Population | 2.4.0 ordinary buildings | 2.5.0 ordinary buildings | Target |
| ---: | ---: | ---: | ---: |
| 2,500 | 312 | 334 | 334 |
| 10,000 | 953 | 953 | 953 |
| 50,000 | 3,902 | 4,167 | 4,167 |
| 250,000 | 7,777 | 18,335 | 20,833 |

The 250k example has 839 core and 17,496 outer buildings. It still has a
2,498-building shortfall; held-out seed 102 reaches 16,677 of 20,833. Shortfalls
are explicit, including those caused by constrained land and absent approaches.
The target remains the existing ordinary-building budget, not a certified
housed-population census. `urbanDensity` occupancy is not increased.

POI selection scores candidate buildings once instead of sorting the whole city
for every POI. The local fixed 250k review measured about 2.15 seconds before and
0.69 seconds after. These are individual generation/SVG/GeoJSON runs, not browser
paint or pan/zoom guarantees. More visible buildings increase SVG size: the fixed
250k output is about 6 MiB uncompressed, 752 KiB gzip.

## Compatibility and integration

- Package and output `settlemaker_version`: **2.5.0**.
- URL envelope remains **v1**, GeoJSON **schema 4**, scene **v2**. The village/city
  routing boundary remains 1,000 / 1,001.
- Cities add optional `Scene.buildingCapacity` and GeoJSON
  `metadata.building_capacity`: `basis`, `target`, `placed`, `shortfall`,
  `corePlaced`, `outerPlaced`, `status`. See the [schema notes](../schema-v3.md).
- Scene streets add `kind: 'alley'` and optional local-unit `width`; GeoJSON
  streets add `streetType: 'alley'` and `'park'`. Park greens can carry paths.
- Custom renderers can use linked building IDs and independent glyph width/depth;
  see the [scene contract](../scene-schema.md). Default rendering uses shared
  glyph definitions with `<use>` instances.
- City geometry and generated IDs change. Invalidate generated-tile caches or
  include the deployed generator revision in cache keys. The URL contract does
  not require a payload-version or import-path change.
- The accepted village renderer remains unchanged; both population-1,000 review
  controls are byte-identical to the prior accepted city pass. Other agents'
  subsequent village work is not included in this release.
- Existing major approaches, walls, gate assignments and patch limits remain.
  This release does not establish correctness of every old city river crossing.

## settlemaker-web deployment handoff

Pin the `settlemaker/` submodule to the exact **v2.5.0** release commit. The
existing web build emits `/lib/settlemaker.js` and keeps the site/library import
boundary. Publishing the web master pin triggers its configured Netlify build.
No page-code or FMG payload change is required for these city improvements.

After deployment, verify the live library reports **2.5.0**, then check city
examples at 2,500 and 10,000, a large-city example, and the population-1,000
village control. Retain the explicit capacity shortfall when displaying budget
information. Revert the web pin commit, or publish the prior Netlify deploy, to
roll back. The previous production pin was
`b0a0613d389e2cc1e6e56eb0d8aa32aa57b2005a`.

## Validation

The accepted implementation passed **1,345 tests in 128 files**, TypeScript
compilation, script type checks and the browser bundle build. All 38 fixed and
held-out city cases maintain or increase ordinary-building counts; both village
controls remain byte-identical. The [implementation report](../plans/2026-09-10-city-block-layout-pass.md)
records density exceptions, remaining capacity gaps, generated-output size and
reproduction commands. The release bump also passed 74 output-version, origin,
degraded-generation, city-block and population-routing checks. URL compatibility
and web-build results are recorded in the deployment handoff.

# SettleMaker 4.0.0

All public generation now uses the physical planner. Villages and cities share
one model, rendering pipeline, resident accounting and GeoJSON contract in local
metres. This is a breaking release: read the [migration guide](../migration-physical.md)
before upgrading consumers or regenerating saved maps.

## Breaking changes

- `generateSettlement` and `planSettlement` always return
  `{kind: 'planned', model, svg, geojson}`. `createSettlementModel` and
  `createSettlementSession` use the same physical defaults.
- The legacy city/village generators, renderers, schema-4 exporters and model
  constructors are removed from the package's public entry point. Internal
  layout algorithms remain available to the physical planner.
- GeoJSON uses `metadata.schema: 'settlemaker/physical-plan'` and schema version 1.
  Every coordinate is in local metres, x east and y south. Saved schema-4 data
  must retain its old interpretation or be regenerated; changing metadata alone
  does not migrate coordinates, feature types or IDs.
- Retired `svg`, `geojson` and `village` generation options throw helpful errors.
  Use shared `theme`, `style`, `skin`, `render` and explicit render/export APIs.
- Old `urbanDensity` and `coreCapacity` inputs produce diagnostics. Use
  development occupancy controls and `corePopulation` instead.
- Public tiling defaults to one metre per unit and derives zoom from actual map
  extent. Its old population argument no longer estimates scale.
- The old database gate importer is retired because its schema cannot represent
  physical entrance lines without inventing legacy classifications.

## Shared generation and integration

An explicit `development.preset` selects city or village layout. Otherwise
`options.engine` overrides `burg.engine`, with automatic selection choosing
village through 1,000 people and city above it. Both return the same output type.

Retained sessions support physical viewport rendering for both layouts. Measured
water and river inputs use the shared metre-based site reader for cities and
villages. Old regional `villageTheme` URL colours are migrated to shared styles.

The documentation, runnable examples and gallery now describe and exercise the
physical-only API. Settlemaker-web removes the legacy planner toggle, retains
saved-link layout intent and uses the shared viewport renderer for all maps.
The website is deployed separately from this npm package.

## Verification

The migration passed 1,614 engine tests, 174 web tests, TypeScript/build checks,
runnable documentation examples, and browser checks covering villages, large
cities, rural development, saved URLs, SVG downloads, tiling and printing.
Package verification additionally checks the installed release artifact in an
isolated consumer before publication.
